Password recovery boundary acceptance

- Guest direct `/reset-password` without a recovery callback must resolve to the inactive recovery-link UI.
- A normal signed-in session visiting `/reset-password` directly must not receive the password reset form; only a genuine Supabase `PASSWORD_RECOVERY` event authorizes it.
- A valid recovery email flow still requires a real email/recovery token and is not simulated in production acceptance.
- Existing `/forgot-password` remains the recovery request entry point.
- Existing `/account/security` remains the normal signed-in password/email change path with current-password verification.
